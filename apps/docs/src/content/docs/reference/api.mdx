The mobile pipeline talks to one endpoint. Everything else — sessions, consent, admin — is
support around it.

The contract lives in `packages/openapi`. The Zod schemas in `src/schemas.ts` are what the API
validates against at runtime. `openapi.yaml` is the published specification.

## `POST /v1/commands`

Upload one voice buffer and the current screen context. Receive a validated action plan, or an
instruction to ask again.

The specification declares the production base URL as `https://api.echoguide.app/v1`.

### Headers

| Header | Required | Value |
| --- | --- | --- |
| `X-Install-ID` | Yes | Identifies the installation, not the person. Sessions are bound to it. |
| `X-Idempotency-Key` | Yes | A UUID generated by the client. A retried upload with the same key never executes or bills twice. |
| `Content-Type` | Yes | `application/json` |

### Request body

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `audio_base64` | string | Yes | 16 kHz mono PCM 16-bit, base64-encoded |
| `duration_ms` | integer | Yes | 400 to 15 000 |
| `language` | `am-ET` \| `en-US` | No | Defaults to `am-ET` |
| `screen_context.current_package` | string | Yes | Package name of the foreground app |
| `screen_context.view_tree_summary` | string | Yes | The reduced view tree the planner sees |

**Screen context is data, never instruction.** Anything on screen that reads like a command is
still only data to the planner — see [Security](/architecture/security/).

### Response body

| Field | Type | Present when |
| --- | --- | --- |
| `command_id` | uuid | Always |
| `status` | enum | Always — see below |
| `reprompt_reason` | string | `REPROMPT` or `REJECTED` |
| `action_plan` | `ActionPlan` | `ACCEPTED` or `CONFIRMATION_REQUIRED` |
| `speech_response_text` | string | When the reply has variable content to speak |

| Status | Meaning | Phone does |
| --- | --- | --- |
| `ACCEPTED` | Plan passed validation | Executes it |
| `CONFIRMATION_REQUIRED` | Plan contains a destructive step | Speaks the step, waits for yes |
| `REPROMPT` | Transcript failed the confidence gate | Asks again, at most twice |
| `REJECTED` | Plan failed schema or allowlist validation | Speaks the failure, runs nothing |

### Error responses

| Code | Cause |
| --- | --- |
| `400` | Missing headers, or audio shorter than 0.4 s |
| `429` | Rate limit exceeded |
| `500` | Provider failure or timeout |

## The action plan

A plan is a list of steps, and every step is one of exactly **five** action types. Anything
else is rejected before it reaches the phone.

| Field | Type | Notes |
| --- | --- | --- |
| `plan_id` | uuid | |
| `package_name` | string | The app the plan acts in |
| `steps` | `ActionStep[]` | Executed in order |
| `requires_user_confirmation` | boolean | Defaults to `false` |

| `ActionStep` field | Type | Notes |
| --- | --- | --- |
| `step_id` | uuid | |
| `action_type` | `TAP` \| `SCROLL` \| `TEXT_INPUT` \| `BACK` \| `HOME` | The allowlist |
| `target_node_id` | string | Node in the reduced view tree |
| `payload` | string | Text for `TEXT_INPUT` |
| `is_destructive` | boolean | Forces a spoken confirmation |

## Schema source

Both files, as they are in `packages/openapi`.

<TabItem label="TypeScript">

```ts
export const ActionStepSchema = z.object({
  step_id: z.string().uuid(),
  action_type: z.enum(['TAP', 'SCROLL', 'TEXT_INPUT', 'BACK', 'HOME']),
  target_node_id: z.string().optional(),
  payload: z.string().optional(),
  is_destructive: z.boolean().default(false),
});

export const ActionPlanSchema = z.object({
  plan_id: z.string().uuid(),
  package_name: z.string(),
  steps: z.array(ActionStepSchema),
  requires_user_confirmation: z.boolean().default(false),
});

export const CommandRequestSchema = z.object({
  audio_base64: z.string(),
  duration_ms: z.number().min(400).max(15000),
  language: z.enum(['am-ET', 'en-US']).default('am-ET'),
  screen_context: z.object({
    current_package: z.string(),
    view_tree_summary: z.string(),
  }),
});

export const CommandResponseSchema = z.object({
  command_id: z.string().uuid(),
  status: z.enum(['ACCEPTED', 'REJECTED', 'REPROMPT', 'CONFIRMATION_REQUIRED']),
  reprompt_reason: z.string().optional(),
  action_plan: ActionPlanSchema.optional(),
  speech_response_text: z.string().optional(),
});
```

## Where the code differs today

The tables above follow the Zod schemas. The YAML and the handler in
`apps/api/src/modules/commands/commands.module.ts` have drifted from them.

:::caution[Known drift]
- **`openapi.yaml`** has no `language` or `speech_response_text`, and types `action_plan` as a bare array of steps rather than an `ActionPlan` object.
- **The handler** transcribes every request as `am-ET`, ignoring `language`.
- **The handler** omits `command_id` on `REPROMPT` and `REJECTED`, and falls back to a non-UUID `cmd-<timestamp>` id.
- **The handler** returns the internal error message in the `500` body. The design says internal detail stays server-side.
:::

A request example in Kotlin and TypeScript is on [Voice commands](/guides/voice-commands/#sending-a-command).
